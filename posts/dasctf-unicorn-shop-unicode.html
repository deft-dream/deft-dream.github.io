🔍 分析：单字符价格约束

错误信息泄露机制

尝试不同的 price 值，观察错误信息：

# 多字符价格 → 被拦截
price=1.0  → "Only one char(?) allowed!"
price=1337 → "Only one char(?) allowed!"

# 单字符但价格不足 → 余额不够
price=1    → "You don't have enough money!"
price=2    → "You don't have enough money!"

关键约束：price 字段必须恰好是 1 个字符，且该字符的数值必须 ≥ 商品价格。

问题来了：普通 ASCII 字符中，最大的数字字符是 9，数值为 9，远远不够 1337。必须另辟蹊径。

🔧 Unicode数值混淆攻击

原理

Python 2 的 unicodedata.numeric() 函数可以将 Unicode 字符转换为对应的数值。许多 Unicode 字符拥有远超 9 的数值：

字符Unicode名称数值
²U+00B2上标二2
½U+00BD二分之一0.5
ⅧU+2167罗马数字八8
ⅯU+216F罗马数字一千1000
ↁU+2181罗马数字五千5000
ↂU+2182罗马数字一万10000

ↂ（U+2182）虽然在视觉上只是"一个字符"，但其数值为 10000，远超 1337。

Payload

POST /charge
id=4&price=ↂ

服务端处理流程：

  1. 检查 price 字符串长度 → len("ↂ") == 1 ✅
  2. 调用 unicodedata.numeric("ↂ") → 返回 10000.0
  3. 比较价格 → 10000.0 >= 1337.0 ✅
  4. 购买成功 → 返回 flag

结果

📊 总结

漏洞本质

服务端使用 unicodedata.numeric() 将用户输入的单个字符转换为数值，但没有对数值范围做上限校验。攻击者利用 Unicode 罗马数字字符（如 ↂ = 10000），在满足"单字符"约束的同时传入任意大的数值。

防御方案

# 正确做法：限制字符必须是 ASCII 数字
if not price.isdigit():
    raise ValueError("Invalid price")

# 或者限制数值范围
value = unicodedata.numeric(price)
if value > MAX_PRICE:
    raise ValueError("Price too high")

💡 类型混淆漏洞的核心：开发者认为"一个字符"等价于"一个小数字"，但 Unicode 标准打破了这个假设。在处理用户输入时，永远不要对字符的"语义"做隐含假设。
